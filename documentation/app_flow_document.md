# App Flow Document

## Onboarding and Sign-In/Sign-Up
When a brand-new user arrives at the platform, they land on a public welcome page that briefly explains the digital agreement and e-signature capabilities. From here, they can click a clearly labeled button to register an account. The registration form asks for the user’s name, email address, and a password meeting minimum security requirements. After submitting, the user receives a verification email. Once the email link is clicked, their account becomes active and they are automatically signed in. Returning users click the sign-in link on the welcome page and enter their email and password to access the application. If a user forgets their password, they can request a password reset by providing their email address, which triggers an email with a secure reset link. The user follows that link to choose a new password and then signs in normally. A sign-out button in the header of every authenticated view ends the session, returning the user to the welcome page.

## Main Dashboard or Home Page
Immediately after signing in, the user sees the main dashboard. The top of the page features a header with the application logo on the left and the user avatar and sign-out button on the right. Below the header, there is a horizontal navigation menu showing links to the Agreements section, the Templates section, and Settings. On the left side, a collapsible sidebar repeats these navigation options along with a “Create New Agreement” button for quick access. The central area of the dashboard displays a table listing all existing agreements created or shared with the user. Each row shows the agreement title, template name, status, and last updated date. At the bottom of the table, pagination controls enable the user to view more records. Above the table, a search bar allows filtering by agreement name or status. The user can click any agreement row to view details or choose the “Create New Agreement” button to start a new workflow.

## Detailed Feature Flows and Page Transitions
When the user clicks “Create New Agreement,” they transition to the Template Selection page. Here they see a grid of cards representing each available template. Each card shows the template name, a brief description, and an edit icon if the user has admin rights. Clicking a template card opens the Dynamic Form page. The form is generated based on the template’s JSON field definitions. The user fills in the required information, and real-time validation highlights any missing or invalid fields. Once the form passes validation, the user clicks “Submit,” which sends the data to a Supabase Edge Function. While the PDF is generated server-side, a loading indicator informs the user of progress. On completion, the new agreement appears in the dashboard with a status of Draft. The user may click on an agreement title to open the Agreement Detail page, which displays the filled data, a PDF preview, and actions such as “Send for Signature,” “Download PDF,” and “Delete.” Choosing “Send for Signature” prompts a modal where the user enters signer email addresses and an optional message. After confirming, the system sends email notifications to each signer and updates the agreement status to Pending Signature.

From the user’s perspective, each signer receives a unique link to the Signing Page. On that page, the signers see the document preview and a signature canvas powered by a shadcn/ui dialog component. Signers draw or upload their signature, and the platform captures metadata such as timestamp and IP address. Once each signer confirms their signature, the Edge Function embeds the signature images into the PDF, updates the document in storage, and changes the status to Completed. The originator and all signers receive confirmation notifications that the agreement is finalized.

Administrators have access to an additional section under Templates where they can create new templates or edit existing ones. The Template Editor page provides a form to assign a name, description, and a list of dynamic fields. Saving updates the template version, and any new agreements will use the latest version. Existing agreements remain linked to the version in use when they were created.

## Settings and Account Management
The Settings page is accessible from the main navigation. Here, users can update their profile information, including name, contact email, and password. They can also configure notification preferences for email reminders or in-app alerts related to agreement statuses. If the platform supports subscription tiers, a Billing section shows current plan details, upcoming invoices, and a form to update payment methods. After making changes, the user clicks “Save” to commit updates. A confirmation toast appears, and the user remains on the Settings page. A link in the sidebar always allows the user to return to the Dashboard or other sections of the app.

## Error States and Alternate Paths
If a user tries to access a protected page without authentication, they are redirected to the sign-in page. When form validation fails, inline messages describe the exact error and highlight fields needing correction. If the Supabase Edge Function fails to generate the PDF or there is a network issue, the user sees an error page overlay with a message explaining the problem and a “Retry” button. In the event of unauthorized access, such as a user attempting to view another user’s agreement, the app shows a 403 Forbidden message and a link to return to the Dashboard. Lost connectivity triggers a banner informing the user they are offline and disables form submissions until the connection is restored. Global error boundaries catch unexpected exceptions and display a friendly prompt to refresh the page or contact support.

## Conclusion and Overall App Journey
From the very first moment a user arrives on the welcome page to the completion of a legally binding digital agreement, the platform guides them through clear, sequential steps. A new user signs up, verifies their email, and lands on the Dashboard to view or create agreements. They select a template, fill out a dynamic form, generate and preview a PDF, and send it for signature. Signers follow intuitive signing links and add their signatures securely. Administrators manage templates and versioning, and users adjust settings or view billing details as needed. Throughout the process, real-time validation, informative toasts, and in-app notifications keep users informed. Error pages and offline indicators ensure graceful recovery from issues. By following this cohesive flow, users can efficiently manage, sign, and finalize digital agreements without missing a single step.
